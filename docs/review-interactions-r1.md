## Code and race review

[FeatureCard](../web/src/Board.tsx#L213) is memoized and owns busy/error state plus the synchronous `inFlight` guard shared by its card/dialog actions. [Visitor bootstrap](../web/src/Board.tsx#L45) stores the promise before returning it, coalesces mounted-board startup/clicks and clears it on rejection. [useResource.updateData](../web/src/hooks.ts#L25) is stable; [voteChanged](../web/src/Board.tsx#L61) uses a functional update, replaces only the matching feature and returns untouched feature references. Project lookups return the existing objects. Concurrent completions for different features therefore apply to current data without overwriting each other's updates or changing sibling props.

[Project choices](../web/src/projects.tsx#L21) keep plain string labels for Base UI matching; [Select.Value](../web/src/ui.tsx#L147) decorates the selected value through the real render-function API. The shared decoration does not replace the control's label/keyboard behavior. No new blocking race or accessibility issue was found in this change. Successful vote/undo/revote persistence is outside these transport-aborted UI checks.
