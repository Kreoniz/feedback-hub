# API contract — 2026-10-21

Same origin API; JSON responses and request bodies, except vote DELETE may omit its body. Errors `{error: string}` with Russian user-safe messages and Retry-After on 429. IDs UUID strings. Timestamps ISO8601. Bounded lists: limit 30 default, max100; offset <=10000. Read/search/filter query strings.

`GET /api/projects` → `{projects:[{slug,name,description,url}]}`. Initial slugs `campus`, `unlikely-ui`, `other`.

`GET /api/form` → `{token:string}` and anonymous signed HttpOnly cookie. Token expires in 2h; reports require age >=2 seconds. Obtain at page mount; refresh on expired token. Visitor cookie is used for voting. Form does not require login.

`GET /api/features?project=campus&q=&status=&sort=votes|new&limit=30&offset=0` → `{items: Feature[], total:number}`. All projects if project empty. Feature `{id,project,project_name,title,description,status,votes,voted,created_at}`. Approved feature only. Never return bug content, moderation metadata, technical context, network identifiers or admin notes.

`POST /api/reports` → always 201 `{id,duplicate:false}` for successful intake, including internal deduplication and honeypot. Never expose whether another visitor sent the same private text: duplicate booleans/status differences are an existence oracle. Each response gets a fresh neutral receipt, never a report ID; no receipt lookup exists. Body `{project,type:'feature'|'bug',title?:string,description:string,details?:string,context?:{page_url?:string,browser?:string,app_version?:string},website?:string,form_token:string}`. Description is the only required content for bugs; title required for features. Context URL must lose query/fragment/credentials on server. Reject sensitive/non-http URLs; context optional. Honeypot website populated: generic success, no report stored. Feature moderation pending; bugs always private. Exact normalized content dedupe within project/type avoids repeated entries internally.

`POST /api/features/{id}/vote` with JSON `{}` and same-origin → `{votes:number,voted:true}`. Idempotently sets the anonymous visitor's positive vote; active retries and own reactivation after undo succeed immediately during cooldown and at lifetime capacity. Requires the signed anonymous cookie (GET form first).

`DELETE /api/features/{id}/vote` with no body and same-origin → `{votes:number,voted:false}`. Optional JSON `{}` is also accepted; a bodyless DELETE needs no Content-Type. Idempotently removes only this cookie's vote; no existing vote also succeeds. Supports positive votes and undo. POST and DELETE share the per-network 30/min request limit, general API limits and exact Origin/Host checks. Both require a valid visitor cookie (400 otherwise), return 404 for missing/private/unapproved/linked features, and serialize with each other and moderation. Counts and `voted` reflect the transaction's result; another concurrent request may subsequently change them. Public/admin vote counts, personalized `voted` flags and public vote sorting use active votes only.

First-ever visitor/feature pairs check the **per-feature, exact-IP 60-second cooldown**. Own reactivation reuses the same retained signed visitor/feature row immediately and leaves all network cooldowns unchanged; it creates no additional cooldown history even after a network change. Undo also leaves cooldowns unchanged and works during cooldown or at capacity. Other/new/reset-cookie voters still wait out the original network cooldown; a new cookie cannot undo the previous cookie's vote. The network rule can briefly block different visitors behind a shared NAT; anonymous cookies are abuse friction, not one-person-one-vote. First-ever visitor/feature pairs consume one of **250,000 persisted lifetime vote slots**. Undo retains an inactive row and never refunds that slot; re-voting reuses it, including at capacity, without growing rows or consuming another slot. DELETE without a prior vote creates no row. Cooldown/budget failures roll back all state. No automatic vote-history deletion is introduced.

Dedupe suppresses one visitor's identical normalized payloads for 24 hours while the previous report is unresolved. Different visitors always create separate reports: cross-visitor deduplication leaks content existence through quota consumption even with neutral replies. An owner can manually link those duplicates. A report after `done`/`closed`, or after the window, creates a new entry so regressions are not silently lost. Transactional intake locking serializes the dedupe check and insert; public acceptance remains indistinguishable.

`POST /api/admin/login` `{password:string}` → `{authenticated:true,csrf_token:string}`; single configured owner, password hash, opaque HttpOnly server session, Secure production, SameSite Strict.

`GET /api/admin/session` → `{authenticated:boolean,csrf_token?:string}`. `POST /api/admin/logout` → 204. Admin mutations after login require `X-CSRF-Token` and same-origin. All /api/admin except login/session require session, unauthorized 401. Session GET sets no-store.

`GET /api/admin/reports?project=&type=&status=&moderation=&priority=&information=&q=&sort=new|old|priority&limit=30&offset=0` → `{items:Report[],total:number}`.

`GET /api/admin/reports/{id}` → Report. Report extends Feature with `{type,details,context,moderation,priority,information,duplicate_of,admin_note,updated_at}`; title may be empty for bugs. `priority`: untriaged|low|normal|high|critical. `information`: sparse|useful|detailed (descriptive score, independent of priority). `moderation`: pending|approved|rejected|spam. Status `new|planned|in_progress|done|closed`.

`PATCH /api/admin/reports/{id}` body optional `{status,priority,information,moderation,duplicate_of:string|null,admin_note}` → Report. Enforce same-project/type duplicates, no self/cycles, reject bug approval. Public duplicates should be hidden when linked; preserve originals and votes without silently transferring votes.

`GET /health/live`, `/health/ready` minimal health, no config. Serve frontend SPA at `/`, `/new?project=campus&type=bug`, `/admin`. Source linking: explicit project wins; otherwise infer only from allowlisted source URL/referrer origin. Context minimized to origin + safe pathname. Do not send location query/fragment. Backend repeats sanitization.
